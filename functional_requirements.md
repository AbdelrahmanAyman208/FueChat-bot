# Comprehensive Functional Requirements Document (FRD)
**Project:** FueBot Academic Advisor
**Version:** 3.0 (Complete System Scope)

This document outlines the exhaustive functional requirements for the entire FueBot Academic Chatbot system. It covers all React Frontend pages (including Dashboards, Chat, and Recommendations), the Node.js API Middleware (Auth, Profiles, Advisor functions), and the Python AI/RAG Engine.

---

## 1. User Interface & Frontend Features (React)

### 1.1 Authentication & Profile UI
- **FR-1.1.1:** The system shall provide login and registration views for students and advisors.
- **FR-1.1.2:** The system shall provide a Profile dashboard displaying a student's GPA, Major, Total Credits Earned, and a categorized list of courses (Passed, Failed, In Progress).

### 1.2 Graduation Requirements Dashboard (`RequirementsPage`)
- **FR-1.2.1:** The system shall display a global progress bar indicating the student's overall graduation completion percentage (e.g., "75% complete").
- **FR-1.2.2:** The system shall display checklists for Core Requirements and Electives, marking them as 'Completed' or 'Pending'.
- **FR-1.2.3:** The system shall display a dedicated **Level 8 Schedule Request** module for eligible students, allowing them to preview schedule groups (Day, Time, Hall) and submit their preference to their advisor.

### 1.3 Course Recommendations Dashboard (`RecommendationsPage`)
- **FR-1.3.1:** The system shall display personalized course recommendations in a card grid.
- **FR-1.3.2:** Each recommendation card shall display a "Ranking Score" (0-100), prerequisites, credits, the target semester, and a detailed justification ("Why recommended").
- **FR-1.3.3:** The system shall allow users to search recommendations by course code/name and sort them by Score, Credits, or Semester.

### 1.4 AI Chat Interface (`ChatPage`)
- **FR-1.4.1:** The system shall provide a modern "Protoplasm" design featuring animated background blobs, glassmorphism styling, and session sidebars.
- **FR-1.4.2:** The system shall render Markdown tables, bold text, and bullet points generated by the AI, displaying a shimmer loading indicator while streaming.
- **FR-1.4.3 (Voice Input/Output):** The system shall allow users to record their voice, auto-submit the transcribed text to the chat, and listen to the AI's response via Text-to-Speech playback.

## 2. Core API & Business Logic (Node.js / Express)

### 2.1 Authentication & Authorization
- **FR-2.1.1:** The system shall provide secure user registration and login using bcrypt password hashing and JWT (JSON Web Tokens) for session validation.
- **FR-2.1.2:** The system shall implement Role-Based Access Control (RBAC), distinguishing between `Student` and `Advisor` user roles.

### 2.2 Student Profile Management
- **FR-2.2.1:** The system shall allow students to view their academic profile, including GPA, major, total credits earned, and specific degree requirements.
- **FR-2.2.2:** The system shall allow students to update their self-reported GPA and Major.

### 2.3 Human Advisor Dashboard
- **FR-2.3.1:** The system shall provide an interface for human advisors to view a list of all students currently assigned to them.
- **FR-2.3.2:** The system shall allow advisors to globally search the student database by name, email, or university ID, and assign unassigned students to themselves.
- **FR-2.3.3:** The system shall allow advisors to manually update a student's course status (e.g., mark a course as passed/failed) or manually enroll them in a new planned course.
- **FR-2.3.4:** The system shall allow assigned human advisors to review, approve, reject, or modify Level 8 schedule requests.

### 2.4 Intelligent Request Routing & Caching
- **FR-2.4.1:** The system shall scan incoming AI chat messages for specific keywords (e.g., "recommend", "register") to determine if it is an advising request.
- **FR-2.4.2:** If advising intent is detected, the system shall route the request to the Python `/api/v1/advise` endpoint, automatically attaching the student's full academic profile.
- **FR-2.4.3:** The system shall cache AI responses in a Redis database for 2 hours, matching on the user ID and exact question text, providing instantaneous replies to repeated queries and handling cache-misses dynamically.

## 3. AI & RAG Engine (Python / FastAPI)

### 3.1 Document Ingestion & Vector Storage
- **FR-3.1.1:** The system shall ingest the academic handbook PDF using a tri-strategy approach (`pdfplumber`, `tabula`, `camelot`) to accurately extract text and curriculum tables.
- **FR-3.1.2:** The system shall automatically clean extracted text by stripping unsupported Arabic noise characters and fixing known CID font ligature bugs (`cid:415` -> `ti`).
- **FR-3.1.3:** The system shall support Hybrid Search, storing document chunks in both a dense vector store (ChromaDB/FAISS) and a sparse keyword index (BM25).

### 3.2 Retrieval-Augmented Generation (RAG)
- **FR-3.2.1:** The system shall rewrite follow-up questions using the conversation history (Contextualization) before querying the database.
- **FR-3.2.2:** The system shall execute Multi-Query retrieval for advising questions—automatically generating 3 distinct search queries based on the student's program and level to pull the maximum relevant context.
- **FR-3.2.3:** The system shall use an `EnsembleRetriever` to merge Dense Search (for meaning) and BM25 Search (for exact course codes like "CSC221").
- **FR-3.2.4:** The system shall format AI responses strictly via SSE (Server-Sent Events), escaping newline characters on the backend to prevent stream breakage when generating Markdown tables.

### 3.3 Audio Processing
- **FR-3.3.1:** The system shall provide a `/api/v1/transcribe` endpoint that accepts `.wav` audio blobs.
- **FR-3.3.2:** The system shall transcribe the received audio into English text using the local SpeechRecognition library and return the text to the frontend.

## 4. Environment Configuration
- **FR-4.1.1:** The system shall allow hot-swapping LLM providers (Google Gemini, HuggingFace, OpenRouter) via `.env` configuration.
